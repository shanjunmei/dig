dig · CLI / Web UI·UX 体验优化评估

评估视角：使用者范围：digen 命令行 + GitHub Pages 文档站方法：实跑 CLI + 审查源码/文档

日期：2026-08-16 · 评估对象版本：v1.0.18

一、总体结论

dig 的底层工程素质很高（错误定位到 file:line:col、💡 Fix: 可操作建议、生成安全网、规范的退出码），但“界面层”与“信息架构层”明显滞后于引擎能力：CLI 仅靠 Go 标准 flag 包的原始帮助，文档与实现存在漂移；Web 文档站视觉与中英双语做得好，却缺少开发者最高频的“复制代码”与“可视化依赖图”能力。整体属于“内核强、门面弱”的典型阶段。

B+
CLI 体验（命令/错误处理强，帮助/文档发现弱）
A-
Web 文档站（双语/响应式/视觉好，缺交互深功能）
中
综合优化优先级（文档对齐 > 帮助重构 > 复制/可视化）
说明：本次“Web”指 docs/index.html 这个静态文档站（GitHub Pages）。代码库中没有独立 Web 服务/Playground；cmd/digenv1（59KB 单体旧版生成器）是遗留代码，并非对外 Web UI，详见问题 C7。

二、CLI（digen）体验评估

2.1 当前交互模型

单一命令、无子命令：digen [flags] [packages...]，默认路径 .。成功打印摘要（[digen] generated N/M packages, cost），失败用 log.Fatalf 退出码 1，参数解析错误退出码 2。实跑验证如下：

# 成功
$ digen ./cmd/digen
[digen] generated: ...\cmd\digen\di.go -> ...\cmd\digen\dig_gen.go
[digen] generated 1/1 packages (0 failed), cost: 2.29s
exit=0

# 非法 alias
$ digen -alias=bogus ./cmd/digen
2026/08/16 12:52:18 invalid alias type "bogus", allowed: short, full, obfuscated, numeric
exit=1

# -version（本地非 mage 构建）
$ digen -version
（仅两行空白）

2.2 优势（值得保留）

  • ✅ 可操作错误：每条错误含源码位置与 💡 Fix:，是同类工具里最友好的。
  • ✅ 退出码规范：成功 0 / 参数错 2 / 运行错 1，利于 CI 脚本判断。
  • ✅ 非法 alias 即时报错并列出允许值（清晰）。
  • ✅ 成功有摘要（含耗时、成功/失败计数）——非静默。
  • ✅ 生成安全网：go/types 兜底 + 预填 GitHub issue 链接，绝不产出无法编译的文件。

2.3 问题与优化建议

严重度问题证据优化建议
高文档与实现漂移：-cache / -cachedir 在 README 与 Web 文档的 CLI 参数表中均未列出；-typecheck 在 Web 表中也缺失。用户无法从文档发现缓存与类型检查开关。main.go 注册了 -cache/-cachedir/-typecheck；README 表仅含 7 项（缺 cache 系列）；Web CLI 表（index.html:441-446）仅 6 项（缺 typecheck+cache 系列）。以代码为单一事实来源，生成 CLI 文档表；在 README 与 Web 同步补齐这 3 个 flag，并标注 -cache 默认关。
高默认 -h 帮助体验差：显示完整 Windows 路径 Usage of C:\...\bin\digen.exe；flag 按字母序排列无逻辑分组；-inline 帮助含内部术语 (Phase 3)；无位置参数说明、无示例、无子命令指引。digen -h 输出（flag 包原始格式）。自定义 flag.Usage：显示 digen [options] [packages]、按“输入/生成/诊断/缓存”分组、去掉内部术语、附 2-3 个示例（digen ./...、digen -inline ./...）。
中-version 在非 mage / 非 go install 构建下输出空白（只有空行）。bin/digen.exe -version 实测空白；versionString() 在 version/commit/date 均为空时仅输出换行。降级显示可读信息，如 digen (devel / version unknown) 或“请用 go install ...@latest 获取带版本号的二进制”，并提示 commit 缺失原因。
中错误输出混用标准库 log 时间戳前缀（2026/08/16 12:52:18 ...），且非彩色，对 CLI 用户是噪声。非法 alias 报错带时间戳前缀。用户可见错误改用 fmt.Fprintln(os.Stderr, ...) 或结构化输出；可选支持 --color=auto（TTY 时红色高亮错误）。
中缺少面向工作流的子命令：无 init（脚手架 di.go）、check/doctor（仅校验不改写）、graph（依赖图可视化）、explain（解释某类型如何解析）。对比矩阵自承 dig 缺 DOT 图——这是卖点缺口。仅 main() 单一入口；README 对比矩阵“Graph visualization (DOT)”行 dig 为 ❌。新增 digen init（生成带 //go:build digen 的 di.go 模板）、digen check（干跑校验）、digen graph（输出 Mermaid/DOT 依赖图）。
中无 shell 自动补全（bash/zsh/fish），长 flag 名易拼错。无补全脚本；-cachedir 等长参数靠记忆。用 codegangsta/cli 或 urfave/cli 等库自带补全，或提供 digen completion 子命令生成脚本。
低仓库残留构建产物：bin/ 下有 digen_fix.exe、digen_fix2.exe、digen_new.exe、digen_v2.exe 共 4 个临时二进制；cmd/digenv1 为未文档化的旧版生成器，go install .../cmd/digenv1@latest 可装到混淆用户的旧版。bin/ 目录、cmd/digenv1/main.go。bin/ 加 .gitignore 或清理；在 README 显式说明 digenv1 的状态（遗留/勿用），或移至 internal/。
低非法 -unused 值被静默回退为 error（parseUnusedMode default 分支），不告知用户。main.go:parseUnusedMode 默认分支。非法值也走 log.Fatalf 报错并列出 error|ignore|drop，与 alias 行为一致。

三、Web 文档站体验评估

3.1 优势（做得好）

  • ✅ 中英双语切换：data-en/data-zh 数据驱动，localStorage 持久化；captureOriginal() 在切换前快照中文原文，英文用户无闪烁。
  • ✅ 翻译覆盖率极高：全站 275 处 data-en + 58 处 data-en-html，导航/特性/对比矩阵/版本亮点均双语对齐。
  • ✅ 对比矩阵分组标签页：架构/API/错误/运行时/状态 5 个 Tab，信息密度高且可扫读。
  • ✅ 视觉与响应式：Go 青主题统一、CSS 变量化；断点 968/768/480px 完整，移动端有汉堡菜单。
  • ✅ 语义化结构：内联 SVG favicon、viewport、anchor 平滑滚动。

3.2 问题与优化建议

严重度问题证据优化建议
高文档漂移（同 CLI C1）：Web CLI 参数表漏列 -typecheck/-cache/-cachedir。index.html:441-446 仅 6 行。与 README 同步补齐（建议由代码生成，避免再次漂移）。
高无代码复制按钮：文档站核心动作是“复制 di.go / main.go / dig.Build 片段”，但每个 <pre> 都没有复制按钮。全文无 clipboard/copy 逻辑；main.js 未实现。为每个代码块右上角加“复制”按钮（navigator.clipboard + 成功反馈），这是开发者文档最高 ROI 的改进。
中语法高亮不一致：仅部分示例用手写 <span class="c-comment/c-func/..."> 高亮，其余纯文本；维护成本高且观感割裂。index.html:417-427 有手写高亮 span，其他代码块无。统一引入 highlight.js（Go 主题）自动高亮所有 <pre><code>，移除手写 span；或彻底不用高亮保持朴素一致。
中无站内搜索、无左侧粘性目录(TOC)：navbar 滚动仅加阴影，未高亮当前章节；长单页（700+ 行）靠人工滚动定位。main.js 仅监听 scrollY>10 加阴影，无 scrollspy 高亮、无 TOC、无 search。加左侧/顶部粘性 TOC + scrollspy 高亮当前 section；可选轻量客户端搜索（如 Pagefind / lunr）。
低无深色模式：代码块用深色背景 #1e1e2e，但整站仅浅色，无法跟随系统偏好。CSS 仅浅色变量。加 prefers-color-scheme 或手动切换；与代码块深色风格统一。
低缺依赖图可视化 / 交互示例：作为 DI 工具，图形化展示依赖解析是天然卖点，当前完全没有；示例仅罗列名称，不可点开看代码。示例区为静态列表（index.html:565+）。接入 digen graph 产出的 Mermaid 图嵌入文档；示例卡片可展开查看源码或跳转仓库。

四、综合优先级路线图

P0 · 立即可做（半天内）

  • 文档对齐：把 -cache/-cachedir/-typecheck 补进 README 与 Web CLI 表
  • 清理 bin/ 残留二进制，说明 digenv1 状态

P1 · 高 ROI（1–2 天）

  • 自定义 CLI Usage/-h（分组+示例+位置参数）
  • 代码块“复制”按钮（Web）
  • 统一语法高亮（Web）
  • -version 降级可读信息；非法 -unused 报错

P2 · 体验跃迁（数天）

  • 子命令 init/check/graph/explain
  • shell 自动补全
  • 左侧 TOC + scrollspy 高亮 + 站内搜索（Web）
  • 错误输出去时间戳 + 可选颜色

P3 · 锦上添花

  • 依赖图可视化 / 交互示例 Playground（Web）
  • 深色模式
  • 版本亮点时间线折叠

五、给使用者的“第一小时”体感总结

新用户按 Quick Start 走通 go install → digen ./... 是顺的（错误友好、摘要清晰）。但一旦他想“开缓存加速”“看依赖图”“复制示例代码片段”，会连续撞墙：文档里查不到缓存开关、文档站没有复制按钮、也没有图形化依赖图。门面层的这三处缺口，是体感从“好用”掉到“勉强”的关键转折点。优先补 P0/P1，体感即可明显上一个台阶。

评估基于实跑 bin/digen.exe（v1.0.18 本地构建）、审查 cmd/digen/main.go/version.go、docs/index.html、docs/assets/* 与 README。退出码与错误行为均经实测。本报告为体验评估，未改动任何源码；如需落地 P0/P1 的快速修复（文档对齐、复制按钮、自定义帮助、版本降级），可继续委托实现。
