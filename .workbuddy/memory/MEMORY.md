# dig 项目长期笔记

## 发布纪律（重要）
- **未经用户明确许可，绝不可把任何版本标记为「已发布」**。具体包含：版本徽章、README「当前版本 / Current version」、对比矩阵「最新版本 / Latest version」、CHANGELOG 的带日期版本头（如 `## [vX] - 2026-...`）、GitHub Pages 的版本亮点时间线条目、prompt 里的 `@vX` 安装 pin。
- 用户会**明确告诉我**某个版本是否准备发布。在此之前，版本头一律用 `## [Unreleased]`，文档只描述代码「当前行为」，不预设版本号与发布日期。
- 代码层面的功能/约束文档（如 README 关键约束、生成安全网说明、示例计数）应**如实反映当前工作区代码**，即使该功能尚未随某个版本发布——但不得出现上述「已发布」标记。
- 当前最新**已发布**版本：v1.0.18。v1.0.19（及之后任何版本）的工作在用户说「发布」之前都视为未发布。
