## GitHub Pages 增加中英文切换
- `docs/index.html` 在每个可翻译元素上加 `data-en`（纯文本）或 `data-en-html`（含 `<code>`/`<strong>` 等标签）属性，原文（中文）作为默认，代码块保持不变。
- `docs/assets/js/main.js` 增加 i18n 逻辑：捕获原始中文 → `localStorage`(key `dig-lang`, 默认 `zh`) 持久化 → 切换 textContent/innerHTML，并同步 `<title>` 与 meta description、按钮高亮。
- `docs/assets/css/style.css` 增加 `.lang-switch` 分段控件样式（桌面/移动端均显示）。
- 导航栏右上加入「中文 / EN」切换按钮。
- 注意坑：`data-en-html` 内若需显示字面 `<pkg>`，属性里要写成 `&amp;lt;pkg&amp;gt;`（双重转义），否则 `innerHTML` 会把它当成真实标签吞掉。
- 部署方式同前：仓库 Settings → Pages → Deploy from a branch → main → /docs。本地预览 `python -m http.server` 于 docs/ 目录。

## digen 生成器 bug：闭包内裸函数调用未拦截未导出符号
- 现象：闭包体里调用同包未导出函数 `buildAuditAuthorizer(authMgr, cfg)`，digen 提升闭包到主包时补包前缀变成 `pkg.buildAuditAuthorizer(...)`（非法，未导出不可跨包引用），却静默 exit 0 产出无法编译的代码，仅 `go build` 时才报 `name buildAuditAuthorizer not exported by package pkg`。
- 根因：`collectTypeNameAndUsedPkgs`（`internal/extractor/extractor.go` ~L2060）给跨包函数补前缀时**不校验是否导出**；而唯一可见性守卫 `checkMethodVisibilityInClosure` 只检查 `SelectorExpr`（方法调用 `x.Method()`），漏掉了**裸标识符调用** `fn(args)`。
- 修复：
  1. 新增 `checkFunctionVisibilityInClosure`（仿 `checkMethodVisibilityInClosure`），遍历闭包体内所有 `CallExpr`，对裸 `Ident` 调用走 `checkGenerationVisibility` 拦截跨包未导出符号（同包/导出/内建一律放行）。
  2. `checkGenerationVisibility` 的 switch 增加 `*types.TypeName` 分支，使类型转换 `T(x)` 中的未导出跨包类型也被拦截（同函数调用一条路径覆盖）。
  3. 在 `handleFuncLit` 中于方法可见性检查之后调用新检查。
- 回归测试：新增失败示例 `example/gen_failures/closure_private_fn/`（pkg/item.go 含未导出 `buildAuditAuthorizer` + `Module()` 闭包调用它；主包 `di.go` 调 `pkg.Module()`）。现在 digen 直接报 `func "buildAuditAuthorizer" is private in package ...pkg and cannot be used from package ...closure_private_fn (generation target)` 且不产出文件。
- 验证：核心代码编译通过；27 个失败示例全部 error；7 个成功示例全部 build 通过；新示例源码可编译（不影响 `go build ./...`）。
- 复现/验证命令：`go build -o digen_debug.exe ./cmd/digen/` 后用 `./digen_debug.exe -out=dig_gen.go "github.com/shanjunmei/dig/example/gen_failures/<name>"`（注意 digen 把位置参数当 import path，不是目录路径，否则报 "not in std"）。
