## dig: 修复 context 注入生成无法编译代码（未被拦截）

- 现象：provider（构造函数）若声明 `context.Context` 参数，digen 在外层作用域写出 `NewDB(ctx)`，但 `ctx` 只在内层 `func(ctx context.Context) error` 定义 → `go build` 报 `undefined: ctx`。digen 仍退出码 0，静默写出坏代码。
- 根因：provider 在 `InitApp` 内被急切解析，早于运行时 ctx 的产生；context 注入只应对 `Invoke`（运行在内层 func 内）合法。生成器仅做 `format.Source`（gofmt），**无编译/类型检查**，且 extraction 阶段拦截对此全部放行。
- 修复：`internal/extractor/extractor.go` 新增 `checkProviderContextParams`，在 `handleProvide`（非闭包）与 `handleFuncLit`（闭包）两条 provider 路径上加拦截，带 `💡 Fix:`，退出码 1 且不写文件。Invoke-with-context 不受影响。
- 验证：复现用例现在生成期报错（di.go:行:列 + Fix），无 dig_gen.go 写出；`go build ./...` 与 `./example/...` 通过；`context_alias`（Invoke 用 context）生成正常。
