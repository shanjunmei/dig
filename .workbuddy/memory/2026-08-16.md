## 生成器运行时正确性探针 + 一个真实缺陷
- 用户追问「依然没查到生成器本身的 bug？」。错误分支层无 bug；但问题是 successtest 只断言重生成的 `dig_gen.go` **能编译**，不验证**运行时语义正确**——最危险的「能编译但接线错」类 bug 全在盲区。
- 隔离探针（外部 temp module + replace=>../dig）：综合泛型 Provider(`*Repo[string]`/`*Repo[int]`) + 闭包 Invoke + `alias=obfuscated` + `inline=true`，真正 `go run` 校验运行时接线。
- 初版把类型/构造器/包级变量写在 `di.go`（带 `//go:build digen`）→ digen 自我保护式类型检查报「internal generator bug」并拒绝。实测这是**契约违反**（di.go 在正常构建被排除，其内符号对生成代码不可见），非生成器 bug；把符号挪到不带 tag 的 `types.go` 后，`full` 与 `obfuscated` 两种 alias 均生成成功且运行时 **PASS** → 证明生成器在硬路径上产出正确可运行代码。
- **真实缺陷（已修）**：`internal/generator/generator.go:156-158` 及 `buildGeneratorBugReport` 把「生成代码类型检查不过」一律谎称为「internal generator bug, 不是你的代码问题」。最常用真实成因是用户把符号定义在 di.go（digen tag 文件，构建期被排除）。已改为准确措辞：说明最可能因 di.go 内定义的符号在构建期不可见，提示挪到无 tag 文件/导入包，并保留「确属内部 bug」时的 issue 上报链接。已验证新消息出现且仍正确拒绝（digen_exit=1），全量回归绿（build/test EXIT=0）。
- 教训：本框架契约为「di.go 只放 dig.Build 接线，领域类型/构造器/包级变量必须定义在别的文件/包」；README/示例默认如此，但**该契约未被清晰报错**，导致易误判为工具 bug。

## 修复：parseUnusedMode 不可达 return（用户报告项）
- 报告：`cmd/digen/main.go` 的 `parseUnusedMode` 在 `fail(...)` 后仍有 `return model.UnusedModeError`，因 `fail` 内部 `os.Exit(1)` 终止程序，该 return 运行时不可达，建议删除。
- 验证存在性：✅ 确实存在。但**仅删除会导致 `missing return` 编译失败**——Go 不会从 `os.Exit` 自动推断 noreturn。
- **关键环境坑（可复用）**：本沙箱的 Go 工具链（go1.26.5 @ `C:\Program Files\Go`）类型检查器**不认可任何函数的 noreturn**——实测 `func f() string { os.Exit(1) }` 也报 `missing return`；`os/proc.go` 的 `os.Exit` 无 `//go:noreturn` 指令源码。因此 `//go:noreturn` 在此环境完全无效（放错/放对位置都救不了），`go/types` / `cmd/compile` 的 `isTerminating` 只认 `panic()` 与结构控制流。
- 最终修复（两文件）：① `parseUnusedMode` 末尾 `return model.UnusedModeError` 改为 `panic("unreachable")`（fail 先 os.Exit，永不到达；panic 是本 TC 唯一被识别的终止符）；② `errors.go` 的 `fail` 保留 `//go:noreturn` 注释（合规工具链上才生效，无害），gofmt 要求指令前留空 `//` 行使其自成指令注释组。
- 验证：`go build ./...`/`go vet ./...` 绿（stat cache Access denied 仅为模块缓存权限告警，非编译错误）；`gofmt -l cmd/digen` 空；`-unused=bogus` 退出 1 且输出 `invalid -unused value "bogus", allowed: error, ignore, drop`（无时间戳），`-unused=ignore -help` 正常。
- 启示：在本环境写“结尾调用不返回函数”的带返回值函数，必须用 `panic("unreachable")` 收尾，不能依赖 `//go:noreturn`。
